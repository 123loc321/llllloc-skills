# Rule 3 and Rule 4: the run, and the directions

Moved from SKILL.md on 14 Oct 2026, unchanged. Read before any option set and before any run of more than three pages.

## RULE 3 — DESIGN THE RUN, NOT THE PAGE

One layout repeated more than three times is a sequence problem. Before the fourth copy, set the alternation: vary PLACEMENT and SCALE across the run, never type sizes, margins or block order. A usable run of three: content left, content right, full bleed. Scale must jump. Exception: when every page carries a different picture, the picture is the variation and the frame stays identical.

Half-empty pages are a count problem. When every page ends at 50 percent, MERGE pairs that are one idea split in two. The writing usually already has the structure: read a paragraph for named items and lay them out as labelled items.

## RULE 4 — THREE OR FOUR DIRECTIONS, RENDERED, THEN HE PICKS

Never accept the first arrangement. It is the most probable one, so the most ordinary.

- THE THREE DIALS: VARIANCE (centered and calm, to off-axis, to asymmetric), DENSITY (spacious, to comfortable, to packed), MOTION (still, to one accent move, to scroll-driven). An option set moves ONE dial and holds the other two.
- Render before choosing: build each far enough to look at, screenshot every one, put them side by side. A broken option is not an option.
- Same content on every option, each tagged, one line of trade-off each, and say which you would pick. Vary the ground and the crop first. Eight options on the same white ground read as one.
- When he answers with criteria instead of a pick ("lean, minimal, easy to edit"), the criteria are the direction. Build the one thing that satisfies every word, render it, say which option it came from.
- THE SKELETON TEST: strip the copy. If the bare structure no longer says what the page is, the design is in the text size. Commit to one decisive move, then quiet everything else.
- Keep the option set in its own `LAYOUT OPTIONS - <archetype>` group at the end of the file. It is the record of what he rejected. He picks before anything rolls out.

## VISITOR MODE

VISITOR MODE decides how far to push. PERSUADE and EXPERIENCE (a deck, a key visual, a poster, a pitch): asymmetric, dramatic, display type carries the voice. OPERATE and READ (a panel, a tool, a spec sheet, a dashboard): predictable structure, stable density, the tool disappears into the task. Most of his work is PERSUADE. His plugin panels are OPERATE. On a website or app, PERSUADE and EXPERIENCE may use depth (parallax, mask, zoom continuity), one signature motion moment, a custom cursor or WebGL when the subject earns it, and the first screen shows a hint of the next section. OPERATE and READ get none of these: no decorative motion, feedback only. `llllloc:task-app-builder` builds both modes.
